# Трекер полезных привычек (Django REST Framework)

Бэкенд-часть сервиса для формирования полезных привычек по мотивам книги «Атомные привычки» Джеймса Клира. Пользователь описывает привычку в формате «я буду [ДЕЙСТВИЕ] в [ВРЕМЯ] в [МЕСТО]», а сервис присылает напоминания в Telegram.

## Возможности

- Регистрация и авторизация по JWT (вход по email).
- CRUD полезных и приятных привычек. Каждый пользователь работает только со своими привычками.
- Список публичных привычек других пользователей (только чтение).
- Пагинация: 5 привычек на страницу.
- Валидация привычек по правилам из задания.
- Напоминания в Telegram по расписанию (Celery + Celery Beat + Redis).
- CORS для подключения фронтенда.
- Документация API: Swagger и ReDoc.

## Стек

- Python 3.14, Django 5.2, Django REST Framework
- PostgreSQL
- djangorestframework-simplejwt
- django-cors-headers
- drf-yasg
- Celery, django-celery-beat, Redis
- Poetry для управления зависимостями

## Структура проекта

```
config/    настройки проекта, urls, настройка Celery
users/     модель пользователя (email + tg_chat_id), регистрация
habits/    модель привычки, валидаторы, права, пагинация, задачи Celery, отправка в Telegram
```

## Модель привычки

| Поле | Описание |
|------|----------|
| `user` | создатель привычки |
| `place` | место выполнения |
| `time` | время выполнения |
| `action` | действие |
| `is_pleasant` | признак приятной привычки |
| `related_habit` | связанная привычка (только приятная) |
| `periodicity` | периодичность в днях (по умолчанию 1, максимум 7) |
| `reward` | вознаграждение |
| `duration` | время на выполнение в секундах (не больше 120) |
| `is_public` | признак публичности |
| `last_reminded` | дата последнего напоминания (служебное поле, только чтение) |

### Правила валидации

1. Нельзя одновременно указать связанную привычку и вознаграждение.
2. Время выполнения не больше 120 секунд.
3. В связанные привычки попадают только приятные привычки.
4. У приятной привычки не может быть вознаграждения или связанной привычки.
5. Периодичность от 1 до 7 дней: нельзя выполнять привычку реже раза в неделю.

Дополнительно: привычку нельзя связать саму с собой или с чужой привычкой.

## Установка и запуск

### 1. Клонирование и зависимости

```bash
git clone <ссылка-на-репозиторий>
cd <папка-проекта>
poetry install
```

### 2. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```
SECRET_KEY=            секретный ключ Django
DEBUG=                 True или False
DB_NAME=               имя базы данных
DB_USER=               пользователь PostgreSQL
DB_PASSWORD=           пароль
DB_HOST=               например, localhost
DB_PORT=               например, 5432
TELEGRAM_BOT_TOKEN=    токен бота от BotFather
CELERY_BROKER_URL=redis://localhost:6379/0
```

Файл `.env` не должен попадать в репозиторий.

### 3. База данных

Создайте пустую базу в PostgreSQL (имя должно совпадать с `DB_NAME`), затем:

```bash
poetry run python manage.py migrate
poetry run python manage.py createsuperuser
```

### 4. Запуск сервера

```bash
poetry run python manage.py runserver
```

API будет доступен на `http://127.0.0.1:8000/`.

## Telegram-бот

1. Откройте в Telegram чат с [@BotFather](https://t.me/BotFather) и создайте бота командой `/newbot`. Укажите имя и username (должен заканчиваться на `bot`).
2. Токен, который выдаст BotFather, запишите в `.env` в переменную `TELEGRAM_BOT_TOKEN`. Никому его не передавайте.
3. Откройте своего бота и нажмите **Start**. Без этого бот не сможет писать вам первым.
4. Узнайте свой `chat_id`: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите в ответе `"chat":{"id":...}`.
5. Укажите `chat_id` в поле `tg_chat_id` при регистрации или в профиле пользователя в админке.

## Напоминания (Celery)

Для отложенных задач нужен Redis версии 6 или выше.

- **Linux / macOS:** установите Redis из пакетного менеджера.
- **Windows:** подойдёт [Memurai](https://www.memurai.com/) (Redis-совместимый сервер).

Запуск (в двух отдельных терминалах):

```bash
poetry run celery -A config worker -l info --pool=solo
poetry run celery -A config beat -l info
```

Флаг `--pool=solo` нужен только на Windows.

Задача `habits.tasks.send_habit_reminders` запускается каждую минуту. Она находит полезные привычки, время которых совпало с текущим, учитывает периодичность (по полю `last_reminded`) и отправляет напоминание в Telegram пользователю, у которого указан `tg_chat_id`. В сообщении указывается действие, время, место и вознаграждение или связанная приятная привычка.

Расписание хранится в базе (`DatabaseScheduler`), его можно посмотреть в админке в разделе «Периодические задачи».

## API

Все эндпоинты, кроме регистрации и входа, требуют заголовок `Authorization: Bearer <access-токен>`.

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/api/users/register/` | регистрация |
| POST | `/api/users/login/` | авторизация, возвращает `access` и `refresh` |
| POST | `/api/users/token/refresh/` | обновление access-токена |
| GET | `/api/habits/` | список привычек текущего пользователя (по 5 на страницу, `?page=2`) |
| POST | `/api/habits/` | создание привычки |
| GET | `/api/habits/<id>/` | просмотр своей привычки |
| PUT / PATCH | `/api/habits/<id>/` | редактирование своей привычки |
| DELETE | `/api/habits/<id>/` | удаление своей привычки |
| GET | `/api/habits/public/` | список публичных привычек (только чтение) |

### Пример регистрации

```json
POST /api/users/register/
{
  "email": "user@example.com",
  "password": "StrongPass123",
  "tg_chat_id": "123456789"
}
```

### Пример создания привычки

```json
POST /api/habits/
{
  "place": "дом",
  "time": "08:00:00",
  "action": "делать зарядку",
  "is_pleasant": false,
  "periodicity": 1,
  "reward": "чашка кофе",
  "duration": 60,
  "is_public": true
}
```

## Документация

- Swagger: `http://127.0.0.1:8000/swagger/`
- ReDoc: `http://127.0.0.1:8000/redoc/`

Чтобы выполнять запросы в Swagger, нажмите **Authorize** и введите `Bearer <access-токен>`.

## CORS

Разрешённые адреса фронтенда задаются в `config/settings.py` в переменной `CORS_ALLOWED_ORIGINS`. Для развёрнутого сервера добавьте туда адрес фронтенда, а в `ALLOWED_HOSTS` адрес или домен сервера.
